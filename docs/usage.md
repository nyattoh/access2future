# Access移行計画の使い方

現行A（移行計画を作る版）の操作順です。画面の見出しと操作順を実装・統合試験に照らして確認しました。

この版では、取り込んだ構造からフォーム・ページ・帳票と利用形態を確認し、移行計画の草案を作ります。操作範囲は計画の草案までです。コードの生成、データの移行、移行先での動作検証は含みません。サーバーはこのPCの localhost だけで待ち受けます。

実装上の約束は [contracts.md](contracts.md) にあります。

## 始める

- Node.js 22 以上を使います。
- プロジェクトのディレクトリで `npm start` を実行します。
- ブラウザで http://127.0.0.1:7331 を開きます。
- Windows で Access が使えるときは、そのPC上で Access ファイル（`.accdb` / `.mdb`）のメタデータを解析します。
- Access が使えないときは、JSON 解析資料か合成サンプルを使います。

ファイルはこのPC内のローカルサーバーだけで処理します。

## 5つの工程

工程ナビは「データベースを解析」「移行対象を選択」「利用形態を確認」「影響を確認」「計画を作成」です。各画面の見出しは次のとおりです。

### 1. データベースを解析

**どちらか1つのファイルだけでも解析できます。** Accessは画面とデータが1つのファイルに入っている場合も、別々のファイルになっている場合もあります。分からないときは、手元にある1つを選んでください。もう1つある場合だけ追加できます。JSON解析資料も選べます。

「ファイル1」「ファイル2」のどちらの欄だけでも使えます。ファイルを選んだだけでは処理は始まりません。「解析開始」を押すと、選んだファイルの構造を解析します。実データの行は読み出しません。

選んだファイルは選び直せます。「ファイル1を削除」「ファイル2を削除」は画面の選択を取り消す操作で、元のファイルを消しません。選び直しや削除をした後は、古い解析結果を使わず再度「解析開始」を押してください。

解析中は選び直し・削除・先の工程への移動を止めます。「解析を中止」で処理を止め、停止と一時ファイルの削除を待った後に操作へ戻ります。選んだファイルは残るので、そのまま再解析できます。解析に失敗した場合もファイルは残り、再試行できます。

Access解析中は、ファイルごとに「確認済み資産：35 / 127件（27%）」のような実測の件数と割合をプログレスバーで表示します。確認処理を終えたテーブル・クエリ・フォームなどの件数であり、経過時間や残り時間の割合ではありません。未取得・非対応と分かった資産も確認済みとして数え、取得結果は別に示します。全資産の確認が済むと「資産の確認を終え、後処理をしています。」と表示され、100%でも結果の返却までは数十秒かかることがあります。

解析の上限は1ファイルあたり15分です。超えるとエラーに「15分の制限時間内に完了しませんでした」と表示され、結果は作られません。選んだファイルは残るので再試行できます。エラーの近くには、最後に確認できた「74 / 128件（57%）」と停止した段階が残ります。総数を数えている段階で止まったときは割合を出さず「総数を数えている段階で停止」と表示します。

資産の総数を数えている段階は、その処理名を表示します。資産確認が100%になった後も、一時ファイル削除などの後処理が完了するまで次へは進めません。2ファイルはそれぞれの件数と「1 / 2ファイル」などの位置を示します。中止待ちでは最後の実測値を保持し、停止後にバーを消します。JSON資料は、その資料に含まれる資産数を基準に検証します。

リンク先は自動では読み込みません。取得できない参照、不明な参照、曖昧なリンクは、人が確認する項目として残ります。

資料がないときは「合成サンプルを試す」を使います。画面は合成サンプルと表示します。

「選択へ進む」で次へ進みます。

### 2. 移行対象を選択

移行したいフォーム、レポート（帳票）、またはページを選びます。一つも選ばないと「利用形態へ」は押せません。選択は自動では増えません。

ここでいう「ページ」はAccess Data Access Pagesです。Access Data Access Pagesは旧形式のため、選べても非対応の阻害事項が計画に残ります。選ぶと、その対象が使う資産、共有される資産、未選択の機能への影響が横に出ます。これは確認用の候補です。

### 3. 利用形態を確認

利用人数、利用場所、通信は別々の軸です。

- 利用人数: 「一人で使う」または「複数人で使う」
- 利用場所: 「同じPCから」「社内の複数PCから」「社外・遠隔から」
- 通信: 「オフラインでも使う」

同じ画面で、同時編集、権限、既存 Access との共存も答えます。未回答の項目は未確認として計画に残ります。

「影響を確認」で次へ進みます。

### 4. 依存関係と影響を確認

選択したフォーム・ページ・帳票、依存する資産、共有される資産、未選択機能への影響、未取得・非対応を、分けて見ます。

移行先は「Webアプリ」「Excel」「Googleスプレッドシート + GAS」から一つ選びます。表示は利用形態からの相対的な目安です。

移行先を選ぶと「計画を作成」を押せます。

### 5. 移行計画

計画は草案です。要件は未承認として表示されます。要件、根拠、移行手順、検証手順、未解決事項、リスクを読みます。

「Markdownを保存」は `access-migration-plan.md`、「JSONを保存」は `access-migration-plan.json` を、このPCへ保存します。

保存した計画には Mermaid の図が2つ入ります。Markdown では「図（Mermaid）」の節、JSON では `diagrams.flow` / `diagrams.er` です。

- 業務フロー候補: 選択対象から依存する資産までの図です。太線が選択対象、点線が影響を受ける未選択画面からの経路です。
- ER図: 依存範囲にあるテーブルの項目と、Access に定義された関連です。

どちらも取得済みの依存と関連だけから描いた候補で、業務の手順そのものではありません。GitHub、Mermaid 対応のエディタ、https://mermaid.live などで図として表示できます。

前の工程に戻って入力や選択を変えると、計画は作り直されます。

## 資料の区別

画面は出典を次のように分けます。

- 合成サンプル: 説明用の例です。
- Access解析結果: このPCで取り込んだ Access ファイルから取得できた定義です。
- JSON資料（自己申告）: 渡した JSON の内容です。
- 2つのファイルを両方解析したときは、統合した構造資料（メタデータのみ）と表示します。リンクは、資料に明示された接続先の名前とテーブル名が一致するときだけ結びます。それ以外は人が確認します。データだけのファイルでは、選べるフォーム・帳票が見つからないこともあります。
