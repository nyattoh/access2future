# Windows atomic export and DACL preservation

Base: `b81bb1c3f40b0cce3034197275d341e362b60d5b`, PR #13 branch `fix/save-atomic-replace-20261020`. Implementation provider: Codex (`gpt-6.1-sol`). No Cursor implementation task was used.

## Commit contract

The destination is classified before staging. Existing regular files use `ReplaceFileW` with flags **0** and a unique bounded sibling backup. New destinations use `MoveFileExW` with `MOVEFILE_WRITE_THROUGH` and no replace/copy flag. If an existing destination disappears before replacement, error 2 permits one no-replace move. A concurrent destination is never overwritten by either move.

Only documented error **1177** permits recovery from the backup using a no-replace move. If restoration fails, the backup remains as the preserved old copy beside the destination (`.{uuid}.bak`); do not discard it when recovering a failed save. Other replacement errors do not trigger a replacing fallback. Once replacement succeeds, backup deletion is best-effort: its failure leaves a backup but still reports a successful save. This implementation does not promise transactional recovery from hardware failure.

Stage/write/flush/size-check/close still precede commit. The earlier bounded `.{uuid}.tmp` naming fix is retained. Windows API paths use absolute, extended-length UTF-16 paths; no Unicode text is converted lossily. Non-Windows retains `std::fs::rename`; no Unix permission copying is added. The already cached `windows-sys` 0.61.2 is now a direct Windows dependency; no package was fetched.

API references: [ReplaceFileW and its documented partial failures](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew), [MoveFileExW flags](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw).
