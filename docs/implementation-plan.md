## 5. 実装計画案

### 段階0: 対象Accessシステムと利用条件を確認する

成果物は、対象Accessシステムの構成、解析に利用できるファイルと外部参照の範囲、実行環境、利用者、改善目的、情報の扱いの条件。業務担当者の説明を得て、画面外の手作業も確認する。最初の移行先・フレームワーク・データベースは、この段階では確定しない。

開始条件: 計画と検証対象が確認されていること。実装を伴う次段階へ進む際は、対象範囲の実装承認を得る。

### 段階1: DB全体の構造とフォーム・ページの一覧を解析する

最初の開発対象として、ローカルでDB全体の構造、フォーム・ページの選択候補、資産一覧と対応範囲を出力する最小版を提案する。解析を代表業務1つの使用テーブルに限定しない。Accessの既存機能を使う方式を先に検証し、独自のバイナリー解析や複数方式の共通基盤を先行して作らない。

候補範囲は、許可された対象システム内のテーブル構造・リレーション・保存クエリの定義、フォーム／レポートの定義、VBA・マクロ・イベント・外部接続の存在と取得可能な情報。フォームの参照クエリ、関連フォーム、選択肢の参照元、起動する処理なども依存関係の候補とする。データ行の取得とリンク先の読み出しは別の範囲として扱い、全構造の把握を全実データの取得や外部接続の許可と同一視しない。「ページ」は元オブジェクトの種類を確認するまで対応を約束しない。

原本を保全し、コピーまたは合成データを使用する。起動処理・更新クエリ・VBA／マクロ・外部処理を実行させない条件を検証前に整える。コピーだけでは外部システムへの影響を防げるとは限らない。安全な抑止方法が確認できない対象は保留する。

成果物は、資産一覧、フォーム・ページの選択候補、依存関係、出典、取得結果、取得できなかった理由を確認できるレポート。動的に組み立てるSQLやVBAなど、静的な解析だけで依存先を確定できないものは未確認として残す。取得できた関係だけで影響範囲が完全だと判断しない。中間結果は必要最小限の構造化ファイルを候補とし、版と元オブジェクトを追跡できるようにする。将来の拡張用プラグイン基盤は先行して作らない。

終了条件:

- 合成または利用許可を得た代表資料で、既知の資産一覧と出力を比較できる。
- 部分取得・非対応・失敗・未評価を成功と区別して出力する。
- オブジェクト定義の取得結果と、移行先での再現可否を混同しない。
- 接続文字列などに含まれる秘密情報を、外部送信・公開成果物に含めない。
- 原本の保全と起動・外部処理の抑止を確認できる。
- 複数画面が同じテーブルや処理を使う資料で、共有関係と未確認の依存先を表示できる。

### 段階2: フォーム・ページを選び、依存関係と影響から移行範囲を決める

利用者が一覧から移行したいフォームやページを1つ以上選ぶ。名称・種類・取得可能な説明など、識別に必要な情報を示す。画面のプレビュー方法は未検証であり、選択候補を示すために未知の起動処理を実行しない。

選択後に利用形態を確認する導線を検討する。利用人数（一人／複数人）、複数人での同時入力・編集、利用場所（同じPC／社内の複数PC／社外・遠隔）、オフライン利用の必要性を分けて聞く。遠隔利用は、別の場所からアプリを使うことと、既存PCを遠隔操作することを区別する。質問の具体的な項目と表現は、今後の仕様検討で確定する。

選択対象から依存するクエリ、テーブル、関連フォーム、レポート、VBA・マクロ、外部参照を確認する。さらに、それらを共有・参照・更新する未選択の画面や処理を確認する。選択対象、必要な依存資産、未選択機能への影響、未確認事項を分けて表示する。

例えば、選択した「受注入力」と未選択の「請求処理」が同じ受注データを更新する場合、受注入力だけを別DBへ複製して独立稼働させるとは決めない。データの正本と更新責任を決め、共有データを維持して旧新の画面を共存させるか、関連機能まで移行範囲を広げるかを検討する。データを分ける場合は、同期・競合・失敗時の整合性を別途設計・検証する。

必要な依存資産が見つかっただけで、未選択の画面まで自動的に移行対象に追加しない。影響と対応案を示し、利用者が移行範囲を確認する。整合性の維持方法が未解決の場合は、選択範囲だけの移行を実行しない。

この移行範囲に対して、データ、入力、計算、業務規則、権限、帳票、外部連携、共存条件、受入条件を整理する。各要件候補に元資産を対応付け、取得事実、推定、未確認事項、意図した変更を明示する。担当者による確認を受けた部分を、次段階の仕様とする。

Jevは候補の分類や論点評価を行う補助とし、要件の承認者にしない。今回は既存スキルを実際に呼び出したが、製品へのJev組込みは未実装。将来の送信範囲、予算、欠損・無効回答時の扱い、サービスを使えない場合の運用を別途決める。

終了条件: 移行範囲・利用形態・要件候補と未解決事項を区別できる。共有データの正本・更新責任、参照整合性、未選択機能への影響に重大な未確認事項が残る場合は、移行実施可能な計画として扱わず、必要な追加確認を提示する。
